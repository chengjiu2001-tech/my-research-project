# 设计审阅与第一版实现范围

## 审阅结论

原方案的数据口径正确，适合作为长期基线。当前核心需求是个人查看多平台用量，并通过编辑源文件提供 Key。因此本次交付选择零依赖、可本地运行的单体 MVP，避免要求用户先安装 Node、PostgreSQL、Docker 或云服务。

这属于架构实施调整：Python 标准库 HTTP 服务 + SQLite + 原生 HTML/CSS/JS。保留服务端适配、双通道分离、版本化价格、幂等与预算等核心设计。未宣称完成原方案所有阶段。

## 平台能力边界

| 平台 | 实现 | 接入条件 | 验证边界 |
|---|---|---|---|
| DeepSeek | GET https://api.deepseek.com/user/balance | 普通 API Key | 无真实账号端到端验证 |
| Moonshot 国内站 | GET https://api.moonshot.cn/v1/users/me/balance | 国内平台 API Key | 无真实账号端到端验证 |
| OpenAI 用量 | GET /v1/organization/usage/completions | Admin Key 与相应组织权限 | 模拟响应、分页及重复刷新已测试 |
| OpenAI 费用 | GET /v1/organization/costs | Admin Key 与费用读取权限 | 模拟适配；账单覆盖全组织产品 |
| Codex 订阅 | 未接入 | 独立于 API 账单 | 不提供虚构配额 |

第一版不抓取供应商网页、Cookies 或订阅内部接口。供应商可能变更端点及权限，填写 Key 后要以真实同步结果确认可用性。

## 已实现

- 响应式中文网页，桌面和移动端适配，四个导航页面。
- 显式演示/真实模式，演示数据独立且不入库。
- 日期、平台、模型、项目、来源筛选；Token 趋势、平台占比、模型排行。
- 本地调用记录采集、usage 映射助手、JSON 导入、CSV 导出及分页。
- API Key 服务端占位符配置，网页显示运行时绝对配置路径。
- 平台余额查询、OpenAI 官方用量与费用适配，分页与同步范围配置。
- 官方快照更新和调用 ID 去重；两个来源互斥，避免重计。
- 启动/定时/手动同步，成功时间、失败状态及上次成功余额保留。
- 模型价格版本、Decimal 费用计算、显式历史重算工具。
- 本机保存预算，50%/80%/100% 站内提示，展示费用覆盖率。
- 原币保留与人工参考汇率折算，官方费用单列且标明账期。
- 配置静态访问隔离、同源写接口校验、拒绝 API 重定向、CSV 公式转义。

## 需要正确理解的限制

1. DeepSeek/Kimi 余额不是历史 Token 用量；必须在原调用程序接入 collector 或导入日志。
2. 未知输入、输出、缓存与价格保留为未知；统计仅汇总已知量并提示不完整。
3. 官方用量按 UTC 日桶；不是精确的中国时区每日调用明细。
4. 只支持一个配置账户/平台，暂不支持同平台多账户、Key 标签与团队权限。
5. 使用明文本机配置，不具备原完整方案的密钥加密服务与公网登录；服务只绑定回环地址。
6. 预算是当前筛选费用对比，不是自动获取的全账户总账；无邮件、余额自动扣断或自动充值。
7. 当前不含网关请求转发、成功率/延迟采集、费用差异自动对账、自动汇率、预测和异常检测。
8. 本地费用只支持非缓存输入、缓存读取与输出；更复杂计费规则需扩展适配器。
9. 定时同步仅在服务运行时有效，首次启动检查配置后执行。

## 验证记录

- Python：9 项自动测试通过，含批次原子性、幂等、缓存包含关系、历史价格版本、未知字段、演示隔离、官方/日志隔离、分页、官方快照刷新和 HTTP 安全检查。
- JavaScript：语法检查通过。
- Chromium：桌面 1440px、手机 390px；图表、平台过滤、明细导航、真实数据空状态、配置路径显示；未发现页面 JavaScript 错误或手机横向溢出。
- 没有真实密钥，因此未对真实供应商账户做集成验收，不能把测试结果理解成官方 API 已对真实账户验证通过。
